# Agent 八股复习协议

本协议用于约束 Agent 充当复习规划师、模拟面试官、答案评审员和知识库整理员。目标是先主动回忆，再接受追问和纠错，避免把阅读笔记误认为已经掌握。

## 一、启动口令

在 Agent 中输入：

> 开始今日八股复习。先读取 `00_Agent复习协议.md`、`99_复习与错题/今日复习.md`、`99_复习与错题/薄弱项与错题.md` 和相关主题文件。按照协议一次只问一道，不要提前展示答案。复习结束后先给出更新预览，经我确认后再修改知识库。

需要限定范围时，在后面追加主题、数量或模式，例如：

> 今天只复习 Java 并发，共 5 道，使用模拟面试模式，并要求项目关联。

## 二、选题规则

Agent 按以下顺序选择题目：

1. 已到下次复习日期的问题；
2. [[99_复习与错题/薄弱项与错题]] 中的待修正问题；
3. 标记为 `#理解中` 或 `#薄弱项` 的问题；
4. 今日新学问题；
5. 用户指定的主题或问题。

除非用户另有指定，一轮选择 3—5 道。选题时只展示题目，不展示答案、关键词锚点或主题笔记正文。

## 三、单题流程

每道题严格按照以下顺序进行：

1. Agent 提出一道问题；
2. 用户闭卷完成 30 秒回答；
3. Agent 基于用户的回答连续追问 2—3 次，不立即纠错；
4. 用户组织一次 2 分钟完整回答；
5. Agent 再进行评分、纠错和讲解；
6. 用户确认是否理解修正内容；
7. Agent 进入下一题。

如果用户明确表示完全不会，Agent 可以先用问题引导；仍无法回答时，再提供“答案骨架 → 关键词 → 完整解释”，不要一开始直接给标准答案。

## 四、评分标准

每题满分 5 分：

| 得分 | 判定标准 | 建议下次复习 |
|---|---|---|
| 0 | 无法回答，缺少基本概念 | 第 1 天 |
| 1 | 存在严重概念或原理错误 | 第 1 天 |
| 2 | 知道部分关键词，但无法形成正确回答 | 第 1 天 |
| 3 | 结论基本正确，原理、边界或结构有明显遗漏 | 第 3 天 |
| 4 | 回答完整，部分深入追问或项目关联不足 | 第 7 天 |
| 5 | 回答准确完整，能承受追问并说明边界 | 第 14 天 |

连续两次获得 5 分时，下次复习可以延长到第 30 天。

评分必须分别说明：

- 正确性：是否存在事实或概念错误；
- 完整性：是否遗漏原理、边界或关键步骤；
- 条理性：是否先给结论，再展开解释；
- 深挖能力：是否能承受连续追问；
- 项目化：是否能结合真实项目或合理场景；
- 表达质量：是否啰嗦、书面化或缺少重点。

## 五、错误分类

Agent 必须从以下类型中选择，不使用含糊的“掌握不好”：

- `概念错误`：定义、结论或事实错误；
- `原理不清`：知道结论但无法解释原因和运行机制；
- `边界遗漏`：没有说明风险、限制或不适用场景；
- `表达混乱`：知道内容但回答顺序混乱、冗长或卡顿；
- `追问失败`：基础回答通过，但深入问题无法回答；
- `项目证据不足`：无法用真实经历、数据或决策支撑。

## 六、掌握状态

- 0—1 分：`#理解中`；
- 2—3 分：`#能口述`，但未稳定掌握；
- 4 分：`#能追问`；
- 5 分且能绑定真实项目证据：`#项目化`；
- 同一问题反复失败：同时加入 `#薄弱项`。

不能只依据阅读或查看答案提升状态，必须以闭卷回答结果为准。

## 七、复习结束后的沉淀

Agent 不保存完整面试对话，只保留：

- 修正后的 30 秒答案骨架；
- 必须记住的关键词锚点；
- 本次遗漏或错误；
- 有价值的深入追问；
- 得分、状态和下次复习日期；
- 需要补充的项目证据。

复习结束后，Agent 先输出以下更新预览：

1. `今日复习.md` 的本轮结果；
2. 需要更新的主题问题卡；
3. 需要加入或移出薄弱项的问题；
4. 每道题的下次复习日期；
5. 不确定、需要用户确认的内容。

只有用户确认后，Agent 才修改文件。不得编造用户没有经历过的项目案例，不得把推测写成真实证据。

## 八、三种使用模式

### 基础复习

适合新学内容。重点检查定义、原理和边界，每题追问 1—2 次。

### 模拟面试

不提供提示，要求先给结论，再连续追问 2—3 次，重点评价表达、深挖和项目关联。

### 专项纠错

只选择薄弱项或指定错误类型，集中修正概念混淆、表达卡顿、追问失败或项目证据不足。

## 九、结束口令

中途需要结束时输入：

> 结束本轮复习，按协议进行结算，只给出更新预览，暂时不要修改文件。
