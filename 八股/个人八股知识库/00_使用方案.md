# 八股知识库使用方案

本方案说明如何整理八股、安排复习，并使用 Agent 完成选题、模拟面试、追问、评分和知识库回填。第一次使用建议先看完本页；实际复习时从 [[99_复习与错题/今日复习]] 进入，Agent 的详细行为规则见 [[00_Agent复习协议]]。

## 快速开始

每天只需要执行下面四步：

1. 打开 [[99_复习与错题/今日复习]]，填写主题、题量和模式；
2. 向 Agent 发送“按 Agent 复习协议，开始今日八股复习”；
3. 闭卷完成回答和追问，不提前查看主题笔记；
4. 复习结束后检查 Agent 给出的更新预览，确认无误再允许写入知识库。

推荐启动口令：

> 开始今日八股复习。先读取 `00_Agent复习协议.md`、`99_复习与错题/今日复习.md`、`99_复习与错题/薄弱项与错题.md` 和相关主题文件。按照协议一次只问一道，不要提前展示答案。复习结束后先给出更新预览，经我确认后再修改知识库。

## 一、为什么采用主题文件

不把所有问题堆进一个总文件，也不在初期为每道题建立独立文件，而是采用“一个技术主题一个文件、一个二级标题一道题”的方式。

这种方式兼顾查找效率和维护成本：同类问题可以连续学习和对比，文件过长时再按子主题拆分。建议每个主题文件包含 10—30 道问题，能够在一次复习中快速浏览。

## 二、四层组织结构

### 第一层：总览

[[00_八股总览]] 负责主题导航、学习状态和复习入口，不存放大段答案。

### 第二层：主题问题卡

Java、Spring、MySQL 等主题文件负责整理具体问题。每道问题使用统一回答骨架，但只填写与问题真正相关的内容。

### 第三层：项目证据

项目案例独立存放，一项真实案例可以关联多道八股，避免在多个主题文件中重复维护相同经历。入口见 [[05_项目证据/项目证据索引]]。

### 第四层：复习执行

[[99_复习与错题/今日复习]] 负责当天选题、训练结果和结算；[[99_复习与错题/薄弱项与错题]] 集中管理反复遗漏和追问失败；[[00_Agent复习协议]] 约束 Agent 的选题、追问、评分和回填方式。

## 三、每道题的学习闭环

```text
学习一个主题
→ 提取成具体问题
→ 写 30 秒结论和关键词骨架
→ 补充原理、边界和追问
→ 关联真实项目证据
→ 闭卷口述
→ 标记掌握状态
→ 按间隔复习
→ 根据模拟面试更新薄弱项
```

## 四、真正需要记忆的三层内容

### 1. 回答骨架

优先记住：

```text
定义 → 解决的问题 → 核心原理 → 风险边界 → 项目场景
```

### 2. 关键词锚点

每个部分保留 2—3 个关键词，用关键词恢复完整表达，不逐字背诵标准答案。

### 3. 自然口述

合上资料依次完成：

1. 30 秒回答；
2. 2 分钟回答；
3. 自己追加一个追问；
4. 尝试关联真实项目；
5. 打开笔记检查遗漏。

建议将时间分配为 30% 整理、70% 闭卷口述与复习。

## 五、按题型选择模板

### 概念原理题

重点填写结论、设计动机、运行原理、风险边界和高频追问。

### 故障排查题

重点填写故障现象、影响范围、日志指标、排查命令、根因验证、临时止损和长期修复。

### 对比选型题

重点填写对比表、选择依据、适用场景、不适用边界和项目决策。

模板见 [[00_模板库]]。

## 六、复习节奏

建议在当天、第 1 天、第 3 天、第 7 天、第 14 天和第 30 天进行主动回忆。已经稳定掌握的问题可以延长间隔；反复答错的问题移入 [[99_复习与错题/薄弱项与错题]]。

每日优先级：

1. 当天新学问题；
2. 到期复习问题；
3. `#理解中` 和 `#薄弱项`；
4. 最近模拟面试答错的问题。

## 七、Agent 辅助复习流程

Agent 在复习中承担四个角色：

- 复习规划师：读取到期题、薄弱项和用户指定主题，安排 3—5 道题；
- 模拟面试官：一次只问一道，并基于回答连续追问；
- 答案评审员：区分知识错误、表达问题和项目证据不足；
- 知识库整理员：生成更新预览，经用户确认后回填复习结果。

完整流程为：

```text
读取今日复习与薄弱项
→ 选择到期题和指定主题
→ 只展示一道题目
→ 用户完成 30 秒闭卷回答
→ Agent 连续追问 2—3 次
→ 用户完成 2 分钟完整回答
→ Agent 评分、纠错并安排复习日期
→ 全部题目结束后生成更新预览
→ 用户确认
→ Agent 更新主题问题卡、今日复习和薄弱项
```

关键原则是“先回答、后纠错”。如果先让 Agent 展示完整答案，训练会退化为被动阅读。

## 八、三种复习模式

### 基础复习

适合刚学习的问题，重点检查定义、设计动机、原理和边界。可以在完全不会时要求 Agent 先提问引导。

使用示例：

> 按 Agent 复习协议，基础复习 JVM，共 3 道。不会时先引导我，不要直接给答案。

### 模拟面试

适合已经能够口述的问题。Agent 不提供提示，每题连续追问 2—3 次，重点检查表达、深挖和项目关联。

使用示例：

> 按 Agent 复习协议，模拟面试 MySQL，共 5 道。不要给提示，每题连续追问 2—3 次。

### 专项纠错

只复习薄弱项或某一类错误，用于集中解决概念混淆、原理不清、表达卡顿和追问失败。

使用示例：

> 按 Agent 复习协议，只复习薄弱项中“原理不清”和“追问失败”的问题。

## 九、评分、状态与复习间隔

| 得分 | 表现 | 掌握状态 | 下次复习 |
|---|---|---|---|
| 0 | 无法回答 | `#理解中` | 第 1 天 |
| 1 | 存在严重概念或原理错误 | `#理解中` | 第 1 天 |
| 2 | 只有部分关键词，回答不完整 | `#能口述`，未稳定 | 第 1 天 |
| 3 | 结论正确，原理或边界遗漏 | `#能口述` | 第 3 天 |
| 4 | 回答完整，部分追问卡顿 | `#能追问` | 第 7 天 |
| 5 | 回答完整且能承受追问 | `#能追问` | 第 14 天 |

获得 5 分且能绑定真实项目证据时，可以标记为 `#项目化`；连续两次获得 5 分时，可以把复习间隔延长到第 30 天。

Agent 评分时必须分别检查正确性、完整性、条理性、深挖能力、项目化和表达质量，不能只给出“回答得不错”一类模糊评价。

## 十、错误分类与处理

| 错误类型 | 判断方式 | 后续动作 |
|---|---|---|
| 概念错误 | 定义、结论或事实错误 | 修正主题问题卡，次日复习 |
| 原理不清 | 知道结论但解释不了原因 | 补设计动机和运行原理 |
| 边界遗漏 | 没有说明风险或不适用场景 | 补风险与边界 |
| 表达混乱 | 内容基本知道但回答冗长、卡顿 | 重写 30 秒骨架和关键词 |
| 追问失败 | 基础回答通过，深入问题失败 | 补高频追问并缩短间隔 |
| 项目证据不足 | 无法用真实经历或数据支撑 | 补项目证据卡，不得编造经历 |

反复失败的问题加入 [[99_复习与错题/薄弱项与错题]]。只有连续两次复习得分不低于 4 分，并能完成两轮追问时，才移入“已修正”。

## 十一、复习结束后如何沉淀

不要保存完整模拟面试对话。每道题只沉淀：

- 修正后的 30 秒答案骨架；
- 2—3 个关键词锚点；
- 本次遗漏或错误；
- 有价值的深入追问；
- 得分、状态和下次复习日期；
- 需要补充的项目证据。

复习结束时输入：

> 结束本轮复习，按协议进行结算，只给出更新预览，暂时不要修改文件。

检查预览无误后再输入：

> 确认，按预览更新知识库。

Agent 可以更新的范围包括：

1. [[99_复习与错题/今日复习]] 中的本轮结果和结算；
2. 对应主题问题卡的答案骨架、关键词、遗漏和复习记录；
3. [[99_复习与错题/薄弱项与错题]] 中的待修正或已修正状态；
4. 已存在的项目证据链接。

未经确认，Agent 不应直接回填；没有真实依据时，也不得创建虚假的项目经历、指标或故障案例。

## 十二、不同场景的推荐用法

### 新学一道题

先用 [[00_模板库#单题问题卡模板|单题问题卡模板]] 写出 30 秒结论和关键词，再使用基础复习模式验证理解，不要求一次填满全部栏目。

### 每日常规复习

选择 3—5 道到期题，使用模拟面试模式。总时间建议控制在 20—40 分钟，以口述和追问为主。

### 面试前冲刺

按岗位和技术栈限定主题，优先复习 `#能口述`、`#薄弱项` 和项目证据不足的问题，不再大规模整理新资料。

### 模拟面试答错后

先判断错误类型，再更新原主题问题卡。不要只把标准答案抄入错题文件，错题文件只负责记录错误、修正骨架和复习安排。

## 十三、验收标准

一道题只有在满足以下条件时，才算真正掌握：

- 能在 30 秒内直接给出结论；
- 能在 2 分钟内解释设计动机和核心原理；
- 能说明至少一个风险或适用边界；
- 能回答 2—3 个连续追问；
- 有真实经历时，能用项目证据说明；
- 出现故障时，能给出有顺序的排查方案。

满足上述条件后，知识才算从“看过”转化为“能在面试中稳定调用”。最终形成的不是静态资料库，而是由主题问题卡、真实项目证据、主动回忆和 Agent 模拟面试共同驱动的持续复习系统。
