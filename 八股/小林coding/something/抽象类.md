抽象类（Abstract Class）是 ==Java 中一种特殊的类，它介于“普通的类”和“完全抽象的接口”之间==。

简单来说，抽象类就是一个不完整的模板。它规定了子类“必须包含哪些行为”，同时也可以提供一些“通用的公共行为”。

---

## 核心特征

- 不能被实例化：你绝对不能使用 `new` 关键字直接去创建一个抽象类的对象（如 `new Animal()` 是不合法的）。它只能被子类继承。
- 可以包含抽象方法：使用 `abstract` 关键字修饰的方法称为抽象方法。这种方法只有声明，没有方法体（即没有花括号 `{}`），必须由子类去具体重写（Override）实现。
- 可以包含普通成员：和普通类完全一样，抽象类可以拥有普通的成员变量、构造函数、带花括号的具体普通方法以及静态方法。

---

## 代码示例

我们用一个“图形（Shape）”的例子来直观理解抽象类。因为“图形”是一个抽象概念，它的面积无法直接计算，只有知道是具体的圆形还是矩形才能计算。

```java
// 1. 定义抽象类（作为模板）
abstract class Shape {
    // 属性（所有图形都有名字）
    protected String name;

    // 构造函数（虽然不能 new 抽象类，但子类初始化时会调用它）
    public Shape(String name) {
        this.name = name;
    }

    // 抽象方法：只有声明，没有具体实现（强制子类必须各显神通去实现）
    public abstract double getArea();

    // 普通方法：所有图形通用的公共行为（子类可以直接复用）
    public void display() {
        System.out.println("这是一个" + name + "，它的面积是：" + getArea());
    }
}

// 2. 具体子类：圆形
class Circle extends Shape {
    private double radius;

    public Circle(double radius) {
        super("圆形"); // 调用父类构造函数
        this.radius = radius;
    }

    // 必须重写父类的抽象方法，否则子类也必须是抽象类
    @Override
    public double getArea() {
        return Math.PI * radius * radius;
    }
}

// 3. 具体子类：矩形
class Rectangle extends Shape {
    private double width;
    private double height;

    public Rectangle(double width, double height) {
        super("矩形");
        this.width = width;
        this.height = height;
    }

    @Override
    public double getArea() {
        return width * height;
    }
}

// 4. 测试运行
public class Main {
    public static void main(String[] args) {
        // Shape s = new Shape("未知图形"); // 编译报错！抽象类不能实例化

        // 多态的应用：用抽象类的引用指向具体子类对象
        Shape shape1 = new Circle(2.0);
        Shape shape2 = new Rectangle(3.0, 4.0);

        shape1.display(); // 输出：这是一个圆形，它的面积是：12.56637...
        shape2.display(); // 输出：这是一个矩形，它的面积是：12.0
    }
}
```

---

## 为什么要用抽象类？

1. 强力约束，防止犯错：如果用普通类做父类，你可能会忘记在子类中重写计算面积的方法。而使用抽象类，编译器会强制要求你必须重写 `getArea()`，否则代码根本无法编译通过。
2. 极大提高代码复用性：如示例中的 `display()` 方法，所有图形的展示逻辑都一模一样，直接写在抽象类中即可，子类不需要重复编写。

## 经典面试题：抽象类 vs 接口

|特性|抽象类 (`abstract class`)|接口 (`interface`)|
|---|---|---|
|关键字|`extends`（单继承）|`implements`（多实现）|
|核心定位|表示 “is-a”（是一个），用于代码复用/模板设计|表示 “like-a”（具备某种能力），用于解耦/制定标准|
|方法支持|可以有抽象方法，也可以有普通的具体方法|Java 8前只能有抽象方法，Java 8+支持默认方法和静态方法|
|成员变量|可以定义任意类型的变量（普通变量、常量）|只能是公共的静态常量（默认带 `public static final`）|
# 使用抽象类还是接口？
选择使用抽象类还是接口，本质上是在选择不同的代码建模方式。在实际开发中，最核心的判断标准可以总结为两句话：

- 抽象类：认祖归宗，解决“它是什么”（`is-a`）以及“代码复用”的问题。**重对象**
- 接口：强加契约，解决“它能做什么”（`like-a` / `has-a`）以及“系统解耦”的问题。**重行为**

我们可以通过以下三个具体的维度和场景来决定如何选择：

---

## 1. 优先使用“接口”的场景

在现代 Java 开发中，“接口优先”是一个非常通用的原则，除非你有必须要用抽象类的理由，否则通常首选接口。

## 场景 A：需要定义具备某种能力）

如果两个类在本质上完全不是同一种东西，但它们却拥有相同的行为能力。

- 例子：`Dog`（狗）、`Car`（汽车）、`SuperMan`（超人）。这三个类之间没有任何血缘关系（不能有同一个父类），但它们都可以“移动”。此时，应该定义一个 `Runnable`（可运行的）或 `Movable`（可移动的）接口，让它们分别去实现。

## 场景 B：需要利用“多实现”来摆脱 Java 单继承的限制

Java 的类只能继承一个父类，但一个类可以实现无数个接口。

- 例子：你写了一个 `WeChatPay`（微信支付）类。为了不占用它唯一的继承位，你应该定义一个 `Payment` 接口让它实现。这样，`WeChatPay` 未来还可以自由地去实现 `Loggable`（支持日志）接口或 `Serializable`（支持序列化）接口。

## 场景 C：模块与模块之间的对接解耦

在架构设计中，用于前后端数据传输、或者不同服务之间调用时。

- 例子：定义 Service 业务层时，先写 `UserService` 接口，再写 `UserServiceImpl` 实现类。这样高层控制器（Controller）只依赖接口，实现高内聚低耦合。

---

## 2. 优先使用“抽象类”的场景

## 场景 A：存在天然的血缘关系，且需要“强制统一内部结构”（Is-a / 骨架复用）

当多个类在本质上是同一种事物，并且它们包含了大量一模一样的属性和公共方法。

- 例子：`Cat`（猫）和 `Dog`（狗）在本质上是一个（is-a） `Animal`（动物）。所有动物都有 `name`、`age` 属性，都有 `eat()`（吃东西，逻辑完全一样）的行为，但它们的 `makeSound()`（叫声）各不相同。此时，把 `Animal` 设计为抽象类是最完美的。

## 场景 B：经典的设计模式应用——模板方法模式（Template Method）

如果你想控制一个业务的核心流程框架，允许子类只去实现其中某几个特定的可变步骤，而主流程绝对不准子类修改。

- 例子：设计一个“制作饮料”的流程。
    
    ```java
    abstract class Beverage {
        // 模板方法：固定了做饮料的铁律流程，子类不能改
        public final void prepareRecipe() {
            boilWater();       // 1. 烧水（通用，抽象类直接实现）
            brew();            // 2. 冲泡（多变，留给子类去抽象实现）
            pourInCup();       // 3. 倒进杯子（通用，抽象类直接实现）
            addCondiments();   // 4. 加调料（多变，留给子类去抽象实现）
        }
        // 通用步骤
        private void boilWater() { System.out.println("将水煮沸"); }
        private void pourInCup() { System.out.println("倒进杯子"); }
        // 抽象步骤，留给子类
        protected abstract void brew();
        protected abstract void addCondiments();
    }
    ```
    
    这种控制全局流程并复用代码的架构，接口是绝对无法做到的，必须使用抽象类。

## 4. 现代 Java (8及以后) 的微妙变化

过去，人们常说“想写带有默认实现的方法必须用抽象类”。但从 Java 8 开始，接口引入了 `default`（默认方法）和 `static`（静态方法）；Java 9 甚至支持了接口里的 `private`（私有方法）。

这使得接口在“代码复用”上逼近了抽象类。但请牢记：接口依然不能定义非静态的成员变量（状态）。接口代表的是“纯粹的行为协议”，而抽象类才代表“带状态的事物本体”。
