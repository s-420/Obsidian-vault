## 一、 核心概念：什么是可重入锁？

可重入锁（Reentrant Lock）又名递归锁。

- 定义：同一个线程在已经持有该锁的情况下，可以无需等待、多次重复地进入该锁保护的其他代码块。
- 核心目的：为了解决在同一个线程中发生嵌套调用或递归调用时的自身死锁问题。
- 生活本质：刷一次脸（获取锁）进入大门后，里面的所有房间（嵌套方法）只要是同一把锁管辖的，你都可以直接无阻碍通行。

---

## 二、 核心实现：它是如何工作的？

在 Java 的 `ReentrantLock`（基于 `AQS` 框架实现）或 `synchronized` 底层，可重入锁的实现只依赖于 3 个核心要素：

1. 拥有者线程变量（exclusiveOwnerThread）：记录当前是哪个线程正把持着这把锁。
2. 状态计数器（status / state）：记录当前线程对这把锁“套娃”加锁了多少次。
3. 原子操作（CAS）：确保多个线程在抢锁、改状态时绝对安全。

## 1. 加锁实现逻辑（lock）

当一个线程执行到加锁代码时，底层保安会做三步判断：

- 判断一：看 `status == 0`？如果等于 0，说明锁是空闲的。立刻通过 CAS 把 `status` 改为 1，并把 `exclusiveOwnerThread` 记为当前线程。成功拿到锁。
- 判断二：如果 `status > 0`，说明锁被人占了。此时保安扭头看一眼 `exclusiveOwnerThread`，看看登记的名字是不是当前线程自己？
- 判断三：
    
    - 是自己：允许放行！直接将计数器自增（`status = status + 1`）。这就是可重入。
    - 不是自己：无情拒绝！当前线程进入阻塞队列（CLH 队列）挂起，闭眼睡觉，等待唤醒。
    

## 2. 释放锁实现逻辑（unlock）

当代码执行完退出，需要释放锁时：

- 第一步：直接将计数器自减（`status = status - 1`）。
- 第二步：判断 `status == 0` 吗？
    
    - 不等于 0：说明只是里层套娃释放了，最外层还没执行完。锁依然归当前线程所有，什么都不做。
    - 等于 0：说明最外层方法也执行完了！此时将 `exclusiveOwnerThread` 彻底清空（置为 null），并主动唤醒排队队列里的下一个线程来抢锁。

## 三、 底层源码极简对照

你可以对照下面这段 `ReentrantLock` 底层的真实核心源码（简化版），加深印象：

```java
// 尝试获取锁的核心方法
protected final boolean tryAcquire(int acquires) {
    Thread current = Thread.currentThread(); // 获取当前来执行代码的线程
    int c = getState();                      // 获取当前锁的计数器 status

    if (c == 0) { 
        // 1. 锁是空闲的，抢锁
        if (compareAndSetState(0, acquires)) {
            setExclusiveOwnerThread(current); // 抢成功了，登记自己的名字
            return true;
        }
    }
    else if (current == getExclusiveOwnerThread()) {
        // 2. 锁被占了，但发现“正在用锁的人”就是“我自己”
        int nextc = c + acquires; // 计数器累加（status++）
        setState(nextc);          // 更新计数器
        return true;              // 顺利通行
    }
    
    // 3. 锁被别人占了，抢锁失败，返回 false（后续会去排队）
    return false;
}
```

## 四、 完整逻辑闭环图

$$\text{线程请求锁} \longrightarrow \begin{cases} \text{status == 0} \longrightarrow \text{抢锁成功，status = 1，记录线程 ID} \\ \\ \text{status > 0} \longrightarrow \begin{cases} \text{持锁线程 ID == 自身 ID (重入)} \longrightarrow \text{放行，status++} \\ \\ \text{持锁线程 ID != 自身 ID (冲突)} \longrightarrow \text{去队列排队阻塞} \end{cases} \end{cases}$$

$$\text{线程释放锁} \longrightarrow \text{status--} \longrightarrow \begin{cases} \text{status > 0} \longrightarrow \text{外层未完，继续持有} \\ \\ \text{status == 0} \longrightarrow \text{彻底释放，清空所有者，唤醒排队线程} \end{cases}$$

现在，整个可重入锁从概念、场景、到计数器的加减闭环已经完全连成了一条线。
