在 Spring 中，**代理对象（Proxy）** 的产生是整个 AOP（面向切面编程）功能的核心。Spring 主要通过 **JDK 动态代理** 和 **CGLIB 字节码生成** 这两种底层技术来动态创建代理对象。

整个产生过程是一条从“检测切面”到“动态织入”的自动化流水线，核心逻辑可以拆解为以下几个关键步骤：

------

## 1. 触发时机：在 Bean 生命周期的“初始化后”阶段

正如前面提到的，Spring 拥有完善的 Bean 生命周期。代理对象的产生并不是在 `new` 对象（实例化）的时候，而是在对象已经创建并填充完属性后的 **“初始化后（Post-Initialization）”** 阶段。

这个动作由一个核心组件来完成：**`AnnotationAwareAspectJAutoProxyCreator`**（它本质上是一个 `BeanPostProcessor` 后置处理器）。

当一个普通对象（目标对象 Target）走到生命周期的最后一步时，Spring 会调用它的 `postProcessAfterInitialization` 方法：

```unset
 [1. 原始对象new出来] ──> [2. 属性注入] ──> [3. 执行init方法] ──> [4. 拦截并产生代理对象]
                                                                        │
                                                                        ▼
                                                             BeanPostProcessor 介入
                                                      (匹配切面 ──> 动态选择技术 ──> 生成Proxy)
```

------

## 2. 核心步骤：代理对象是如何一步步生成的？

## 步骤一：匹配切面（筛选 Advisor）

当一个 Bean 走到后置处理器时，Spring 会遍历容器中所有的切面（Aspect），根据切点表达式（如 `@Before("execution(* com.example..*.*(..))")`）进行匹配，判断当前这个 Bean 的方法是否需要被拦截。

- **不需要拦截**：直接返回原始的普通对象。
- **需要拦截**：说明这个 Bean 需要被增强，开启代理对象创建流程。

## 步骤二：选择代理技术（JDK vs CGLIB）

Spring 会根据目标类的结构，自动在两种代理技术之间做出抉择（ProxyFactory）：

1. **JDK 动态代理**：如果目标类**实现了接口**，Spring 默认会选择 JDK 动态代理。
2. **CGLIB 动态代理**：如果目标类**没有实现任何接口**（只是一个普通的类），Spring 就会选择 CGLIB。
   *(注：在 Spring Boot 2.x 及更高版本中，为了减少因强转导致的错误，默认配置已经改为了全量使用 CGLIB 代理，除非显式配置切换)*。

## 步骤三：真正动态生成代理类

## 方案 A：JDK 动态代理的产生原理

JDK 代理利用了 Java 反射包下的 `java.lang.reflect.Proxy`。

- **原理**：它在内存中动态生成一个全新的类，这个新类和你的目标类**实现相同的接口**。

- 核心源码形态

  ：

  ```java
  public Object createProxy(Object target) {
      return Proxy.newProxyInstance(
          target.getClass().getClassLoader(),
          target.getClass().getInterfaces(), // 必须针对接口代理
          new JdkDynamicAopProxy(target)    // 拦截器，里面包含各种通知逻辑
      );
  }
  ```

## 方案 B：CGLIB 动态代理的产生原理

CGLIB（Code Generation Library）是一个第三方字节码生成库。

- **原理**：它在内存中动态生成一个全新的类，这个新类会**继承你的目标类**（作为目标类的子类）。因为是继承关系，所以目标类如果被 `final` 修饰则无法被代理。

- 核心源码形态

  ：

  ```java
  public Object createProxy(Object target) {
      Enhancer enhancer = new Enhancer();
      enhancer.setSuperclass(target.getClass()); // 继承目标类
      enhancer.setCallback(new DynamicAdvisedInterceptor(target)); // 拦截器
      return enhancer.create(); // 动态生成子类字节码并实例化
  }
  ```

------

## 3. 代理对象在运行时是如何工作的？

产生的代理对象外壳里面，包裹着**“原始的目标对象”**和**“切面通知列表（Interceptor Chain）”**。

当外部调用代理对象的方法时：

1. **触发拦截**：调用首先进入代理对象的拦截器（如 `JdkDynamicAopProxy.invoke()` 或 `CGLIB$CALLBACK_0`）。
2. **执行前置链**：把匹配到的切面方法（如 `@Before`）按顺序打包成一条链并依次执行。
3. **反射调用原方法**：通过反射机制（`Method.invoke(target, args)`）真正去调用你写的那个原始类的方法。
4. **执行后置链**：原方法执行完后，再依次执行 `@AfterReturning` 或 `@After` 逻辑。

------

## 4. 特殊情况：循环依赖下的提前产生

这就是我们上一轮聊到的**三级缓存**。如果 A 和 B 互相依赖，且 A 需要被 AOP 代理：

- A 在初始化后才能产生代理对象的正常流程就会被**打破**。
- 当 B 需要注入 A 时，会提前触发 A 的三级缓存工厂。
- 三级缓存的工厂方法内部，会**提前**调用上述的 ProxyFactory 创建出 A 的代理对象（Proxy）并塞入二级缓存。
