## 🐛 踩坑与排查

1. **默认模板不属于当前商家**（现象：桌台复制 0 个，门店本体却已创建上架，形成半完成态）：根因是模板 shopId 归属其他 sellerId；修复为建店前模板归属校验并随分支推送。教训：跨商家资源引用必须在执行前预检。
2. **负责人「已激活」≠「真正进企微企业」**（现象：农业大学店桌台两轮 0/11，接口不报错）：对照万达店（戴怡雯预激活后一次通过）确认预激活是桌台复制与负责人关联的硬前置；待客户拉人后续作。
3. **群活动匹配不唯一（50 个候选）触发安全阻断**：符合设计预期，并据此给脚本新增唯一匹配保护；测试场景走显式跳群通道。
4. **解析脚本缺 dotenv 依赖**：安装依赖、修复 dotenv 路径并为 scripts/ 建立 .env 后通过。教训：脚本仓依赖与凭证引导需固化。
5. **Excel/CSV 自动化连环坑**（接口许可筛单）：CSV GBK 解码、日期列需文本化、COM AutoFilter 值列表 >2 项静默失效、只读模式拒绝改自带筛选、日期条件须用序列号、PS1 文件需 BOM——六个坑全部解决并记录在案，且已作为「实测踩坑勿凭记忆改」章节固化进 SKILL.md。
6. **60020 出口 IP 拦截**（现象：API 通道激活被服务商拒绝，退出码 3）：根因是出口 IP 不在服务商可信名单，动态宽带变 IP 会复发；临时处置 = 用户到服务商后台加白当前 IP（报错自带 IP），长效方案 = 走已加白的云服务器代理（待建）——**未解决，待处置**。
7. **企微不支持识别截图中的二维码**（现象：想让用户远程扫码登录总被拒）：企微登录二维码只能实体屏幕扫码，兜底方案改为 agent-browser `--headed` 在常驻机器屏幕上出码 + 聊天文字通知「请到机器前扫码」。
8. **子 agent 通道多次故障**（当日 8+1 次空返回/超时，涉及 explore/librarian/visual-engineering）：全部降级为主 agent 自执行 + 本地缓存/官方文档直查兜底，未阻塞交付。
9. **周报文件名含长破折号「—」导致按猜测路径读取失败**：工具层小坑，精确 glob 后绕过。

## 📌 今日总结（精华与可复用要点）

- **今日最有价值的是一组建店对照实验**：同样的脚本与流程，负责人预激活的万达店一次通过，未真正进企微的农业大学店桌台 0/11——「负责人预激活」升级为建店 SOP 硬前置，且失败经验已回写 feibing-ops skill，形成闭环。
- **「先录制、再实现、后实战」的 skill 交付路径今天跑通全程**（CDP 抓包 → 方案 → 实现 → 离线测试 → 实战首跑 → 三件套 → 推送），红线断言在首跑就拦下 2 家不同构门店，证明防护前置的设计值得成为所有批量操作 skill 的默认结构。
- **规范沉淀从「个人习惯」升级为「仓库契约」**：三件套约定 + 可视化指南规范入仓，跨 agent/跨工具的一致性不再依赖某个模型的自觉。
- **批量激活的「双通道」设计值得复用**：同一个业务按「人在不在电脑边」拆成 Excel 审批流与 qyapi API 通道，审批规则（写操作必须用户确认）与留痕要求跨通道一致——异构执行路径、统一风控口径，这是无人值守自动化的安全样板。
- **反思**：当日多项产物（页面图片校验、Excel 名单审批、夜巡凭证）卡在「等用户/等客户」环节，业务闭环的最后一公里依赖外部输入，明日计划应把这些催办项显式列出。
- **待补**：NSIS 安装包真实安装回归未做；DailyFlow 迷你窗改动等用户目验后提交；本篇日志基于台账 40+ 条与 ops 留痕整理，个别时间戳在台账中存在乱序，以产物证据为准。
