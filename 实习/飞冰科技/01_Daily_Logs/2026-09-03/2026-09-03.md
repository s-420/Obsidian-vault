## 🐛 踩坑与排查

### 1. 企业微信 81013 推送报错（已定位并沉淀）

- **现象**：批量推送个别人失败。
- **排查链路**：ID 体系 → 非正式成员 → 可见范围。
- **根因**：接口凭证 / 授权过期。
- **产出**：[企业微信 81013 报错排查](../../02_Tech_DeepDive/企业微信81013报错排查.md)（已沉淀为技术专题，含四步排查决策树与三类根因谱系）。

### 2. 接口数据正确 ≠ 客户感知无重复

- **现象**：客户反馈「群重复」，怀疑接口数据异常。
- **排查过程**：核对 76 个关联群，确认接口返回群 id 无重复；企业微信中真实存在多组同名群，店铺把同名群都关联，后台才看似「重复」。
- **结论**：这是业务重名，不是数据重复。去重必须以唯一 id（群 id / 账号 id）为准，绝不按 name，否则误删真实群。

### 3. 「通讯录已删但接口仍激活」的账号状态不一致

- **现象**：离职员工企微通讯录已删，但互通接口授权仍激活，账号数据仍出现在接口返回里。
- **排查过程**：从 6608 账户逐个核对企微通讯录，锁定 9 个异常账号（7 离职 + 2 在职异常），已获客户回执确认。

## 📌 今日总结（精华与可复用要点）

今日主线是「权限 / 授权」：建店激活码、批量关联群权限、裂变群选不到群、企微 81013 凭证过期、客服实名认证，多个问题都指向授权配置。数据口径需持续关注（门店数 9843 vs 11811、客户 / 流失口径 6810w / 15401758），注意每日抽数与数据源一致性。

已沉淀 3 份资产：[企业微信 81013 报错排查](../../02_Tech_DeepDive/企业微信81013报错排查.md)（技术专题）、《新建店铺（单独）.docx》（地址待补）、《今日问题整理与总结 - 2026-09-03.html》（地址待补）。

可复用要点：

- **排查「重复」先分层**：区分「数据重复」（同 id 多次出现）和「业务重名」（不同 id、相同 name），两者处理方式完全不同。
- **去重只用唯一键**：按群 id / 账号 id 去重，绝不按 name，避免误删真实群。
- **账号状态一致性检查**：离职员工需在通讯录与接口授权两侧同时核销，单侧删除会造成「接口仍激活」的隐形残留。
- **推送 / 接口报错先查授权链路**：81013 类报错优先排查 ID 体系 → 成员身份 → 可见范围 → 凭证 / 授权过期。

最终价值：为今日分散的权限 / 授权问题建立统一排查视角，避免逐个零散处理；沉淀 81013 排查文档供团队复用；明确数据口径差异，支撑看板抽数时间协调。
