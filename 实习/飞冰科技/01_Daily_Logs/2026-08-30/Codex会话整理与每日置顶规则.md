# Codex 会话整理与每日置顶规则

## 目标

在不破坏项目归属、不隐藏历史会话的前提下，让大量 Codex 会话更容易辨认，并让当天需要处理的任务集中显示。

## 最终方案

### 1. 标题标签只描述内容，并区分同标签任务

会话标题推荐使用 `[类型] 对象或模块：具体任务`：

- `[BUG] 关联资料：修复文件选择`
- `[BUG] 悬浮窗：修复窗口位置丢失`
- `[优化] 今日日志：改进润色效果`
- `[发布] 发布 v1.0.0`
- `[文档] 创建本地 Bug 记录`
- `[会议] 准备 Agent 业务处理会议`
- `[日报] 08-30`
- `[周报] 08-24～08-30`

项目名称不重复写入标题，项目归属继续由 Codex 项目分组展示。普通任务不添加日期，只有日报、周报、会议等周期性内容使用短日期。

同一项目允许存在多个相同类型标签，但必须使用任务对象、功能模块或具体结果进行区分。发现同一项目已有相同标签时，Agent 应检查标题能否独立辨认；如果标题相似或模糊，应提醒用户，或者在任务内容已经明确且不改变原意时直接补充对象和任务描述。任务范围尚不明确时不得自行猜测。

不使用 `[BUG-1]`、`[BUG-2]` 等单纯编号，也不使用完整日期或重复项目名称解决同标签冲突。

### 2. 置顶区作为“今日工作台”

- 每天只置顶仍需推进或回看的 3～5 条会话。
- 置顶仅代表“今天优先处理”，不代表长期重要性。
- 每晚 23:30 自动取消当天的全部临时置顶。
- 自动清理只取消置顶，不归档、不删除、不重命名，也不改变项目归属。
- 如果以后存在长期关注项，应放入独立的长期关注分区，不与每日临时置顶混用。

### 3. 不使用归档做日常整理

归档会让会话离开常用侧边栏，增加后续查找和回顾成本。因此日常整理只使用内容标签和临时置顶。只有明确不再需要日常查看的会话，才由用户主动决定是否归档；不自动删除任何会话。

## 每日操作流程

### 白天开始工作时

1. 查看当天准备推进的任务。
2. 从不同项目中选择最多 3～5 条会话置顶。
3. 检查标题是否能准确说明内容；必要时调整为 `[类型] 对象或模块：具体任务`。
4. 新建任务时直接使用清晰、具体、可区分的描述，避免多个会话使用相似标题。

### 工作过程中

1. 新任务成为今日重点时可以置顶。
2. 已不再需要当天处理的任务可以提前取消置顶。
3. 会话继续保留在原项目中，不为了排序而移动项目。

### 每晚 23:30

自动任务“每日清理临时置顶”会读取当前置顶任务并全部取消置顶，使第二天的今日工作台重新开始。该操作不会归档或删除历史会话。

## 权威源执行规则

本方案进入权威源后，仅在任务涉及 Codex 会话创建、重命名、整理、置顶、归档、删除或侧边栏管理时触发，不要求普通代码、问答或文档任务主动整理全部会话。

具备 Codex 会话管理能力的 Agent 可以在用户授权范围内执行操作；不具备相应能力的 Agent 只能遵守决策和安全边界，不得通过修改数据库、缓存或自动生成文件模拟侧边栏操作。

日常整理不得自动归档或删除，也不得仅凭时间较早、状态为 idle、标题内容或 Agent 对完成状态的推断执行归档。归档必须由用户明确确认范围，删除必须由用户明确指定目标。

## 最终能实现什么

项目分组负责说明“任务属于哪里”，类型标签负责说明“任务是什么性质”，模块或对象负责区分“具体处理什么”，置顶区负责说明“今天优先做什么”。各层职责清晰，既保留完整历史和项目上下文，也能在同一项目存在多个相同标签时快速辨认，并减少当天查找重点任务的时间。
