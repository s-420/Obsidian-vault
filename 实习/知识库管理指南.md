# 知识库管理指南

> 本指南是**给你（用户）本人**看的操作手册。给 AI Agent 看的版本在 `00_Meta_Templates/AGENT-README.md`，两者分工：本指南教你怎么用，AGENT-README 教 Agent 怎么读。

## 一、目录结构

```
实习/
├── 知识库管理指南.md          ← 本文件（给人看）
├── 00_Meta_Templates/        ← 模板 + 受控词表 + AGENT-README（唯一来源，公司层不复制）
├── 01_Methodology/           ← 通用方法论（不绑定公司）
└── 飞冰科技/                  ← 公司模块（新公司复制此骨架）
    ├── 00_INDEX.md           ← 公司入口
    ├── 01_Daily_Logs/        ← 每日日志
    ├── 02_Tech_DeepDive/     ← 技术专题
    ├── 03_Business_Context/  ← 业务逻辑与架构
    ├── 04_Resume_Assets/     ← STAR 简历资产
    └── draft/                ← 草稿箱
```

## 二、日/周/月工作流

| 频率 | 动作 | 位置 | 模板 | 耗时 |
|------|------|------|------|------|
| 日 | 任务 + 踩坑 + AI 协作 Prompt | 公司 `01_Daily_Logs/日期.md` | daily-log | 10 分钟 |
| 周 | 反复出现的知识点提纯成专题 | 公司 `02_Tech_DeepDive/` | tech-deepdive | 1 小时 |
| 月 | 主导 Feature/重大 Bug → STAR | 公司 `04_Resume_Assets/` | resume-asset | 月末 |

**每日复盘约定**：实习日记录写公司 `01_Daily_Logs/`；vault 的 `每日复盘/当天.md` 只放一条链接指向它，不重复记录。

## 三、改进与溯源流程（重要）

改进对象是**模板/指南/目录结构**（普通笔记只增不改）：

```
1. 复制正本到 draft/ 写新版
2. 定稿后替换正本
3. 文件底部追加 Changelog 条目（版本号 + 日期 + 变更摘要 + 原因）
4. git commit，message 写清"改了啥、为什么"
```

**溯源方法**：
- 看旧版全文 / 回退 → `git log` / `git show`
- 看演进逻辑（为什么这么改）→ 文件内 `## Changelog`
- **不做** v1/v2 副本（目录会膨胀，Agent 检索会混淆）

## 四、常见操作

- **新建笔记**：复制 `00_Meta_Templates/` 对应模板到目标目录，填 frontmatter
- **新增技术栈/标签**：先改 `00_Meta_Templates/受控词表.md`，再使用
- **让 Agent 写代码**：告诉 Agent "读取实习知识库的 03_Business_Context，根据记录的订单状态机生成 Spring 状态转移代码"
